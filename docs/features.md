# 独自機能

upstream(`syuilo/ai`)に対して、このフォークで追加・変更した機能。
バージョンごとの変更は [changelog.md](changelog.md) を参照。

## 学習した語句(キーワード)

`keyword` モジュールが、15〜45分の間隔(平均30分)でグローバルタイムラインのノートを形態素解析して、固有名詞と一部の普通名詞を1つ覚える。
覚えた語句はコレクション `_keyword_learnedKeywords`(`{ keyword, learnedAt, kind }`)に保存される。
`kind` は `proper`(固有名詞)か `common`(普通名詞)。この項目を入れる前に覚えた語にはない。

### 覚える語句

- 固有名詞で、読みがあるもの(辞書にない語や、読みがカタカナでない語は覚えない)。
- 普通名詞は、一般的すぎる語を除いた次のものだけ覚える(`src/modules/keyword/token-filter.ts`)。
  固有名詞の語が埋もれないようにするため。upstream は固有名詞だけ。
  - 細分類が「一般」(「今日」などの副詞可能、「発見」などのサ変可能、助数詞可能は覚えない)。MeCab(IPADIC)では「名詞,一般」。
  - 3文字以上(「天気」「時間」は覚えない)。
  - 英数字だけの語(`site`、`LLM`)と、ひらがなだけの語(「ほんと」「おなか」)は覚えない。
  - 例: 武勇伝、いじめっ子、ジンギスカン、ゴミ箱、リッチテキスト。
  - 固有名詞の語には、この絞り込みをしない(英数字だけの語も覚える)。
- 解析の前に、本文から MFM の記法を取り除く(`mfm-js` で構文木にして、文字だけを取り出す。`src/modules/keyword/strip-mfm.ts`)。
  `tada` などの関数名、`https` やドメイン・パスの一部、絵文字名の一部(`meow` など)が、固有名詞と判定されるため。
  - 取り除く: URL、メンション(`@user@host`)、カスタム絵文字(`:meow_sushi:`、`:name@host:`)と Unicode 絵文字、
    コード(`` ` ``、```` ``` ````)、数式、引用(`>`)、関数の名前と引数(`$[spin.speed=1s …]` の `spin.speed=1s`)、`unixtime`。
  - 残す: 装飾(`**` `~~` `<small>` `<center>` `<i>` と `$[…]`)の中の文字、リンクの表示名(`[表示名](URL)`)、
    ハッシュタグ(`#` を外して中身)、`<plain>` の中身(MFM として解釈しない文字なので、そのまま)、検索(`語 [検索]`)の語、`ruby` の親文字(ふりがなは除く)。
  - 閉じていない MFM(`$[tada 閉じてない`)は、パーサーが全体をただの文字として返す。このときも、関数の開き(`$[tada `)と装飾のタグ(`<small>`)は取り除く。
  - 取り除いた部分は空白にして、前後の語がつながらないようにする。時刻の `12:30:45` は絵文字の記法とみなさず、残す。
  - すでに覚えた語は、この処理では消えない。MFM の名残の語は、`/forget 語句` で消す。
  - 本文に単語として書かれた `https` や `URL` は残るので、気になれば `/forget` で除外する。
- Bot アカウント(プロフィールで Bot にしているアカウント)の投稿は、学習にも「今日よく見かけた言葉」にも使わない(`src/modules/keyword/note-filter.ts`)。
  地震速報や定型文の返信のような Bot の連投が、同じ語として大量に混ざるため。Bot の設定をしていないアカウントは見分けられない。
  すでに覚えた語は、この処理では消えない。気づいた語は `/forget 語句` で消す。
- 解析に渡す投稿は、1件5000文字まで(超えた分は切り捨てる)。他のサーバーの長い投稿が1件混ざるだけで、Sudachi が全体をエラーにするため
  (詳しくは [morph-analyzer.md](morph-analyzer.md) の「注意点」)。
- 人名は、名字・名前だけのもの(細分類が「姓」「名」)を覚えない。
  キャラクター名(例: 初音ミク)や、辞書にフルネームで載っている有名人の名前(細分類が「一般」)は覚える。
  一般の人の名前は辞書に載っていないため、名字と名前に分かれて除外される。
- 形態素解析は MeCab と Sudachi を選べる。詳しくは [morph-analyzer.md](morph-analyzer.md)。

### 学習の間隔

次の学習までの間隔は、毎回、15〜45分から一様に選んで引き直す(平均は30分。`src/modules/keyword/learn-interval.ts`)。
投稿が、いつも同じ間隔で並ばないようにするため。

- 1日に学習する回数は、平均48回(これまでの30分固定と同じ)。
- 学習が失敗しても、次の予約は続く(エラーは、これまでどおり外に出る)。
- 起動してから最初の学習も、同じ範囲の間隔で行う。
- 平均を30分より短くしたいときは、一様ではなく、短い間隔に偏った分布が要る
  (15〜45分を一様に選ぶと、平均は真ん中の30分になるため)。

### 覚える語の選び方

見かけた語のうち、まだ覚えていない語の中から、1回に1語を選ぶ(`src/modules/keyword/pick-candidate.ts`)。

1. まず、固有名詞と普通名詞のどちらから選ぶかを、**固有名詞を60%** の確率で決める。選んだほうに候補がなければ、もう一方から選ぶ。
2. 選んだ側の中から、長い語が選ばれやすいように選ぶ(同じ語が何度も出ていれば、その分選ばれやすい)。

- 確率は `config.json` の `keywordProperRate`(0〜1、未指定なら 0.6)。反映には、Bot の再起動が要る。
- 以前は種類を区別せず、固有名詞が選ばれる割合は、タイムラインの実測で約35%だった(候補の約30%が固有名詞)。
- 候補の数は、100件ごとに、固有名詞が約11語、普通名詞が約25語。固有名詞の候補が空になることはほとんどないので、実際の割合も設定に近い。
- 割合は、ログ(下)と、日次レポートの内訳で確かめる。

### 学習の経過(ログ)

学習(15〜45分ごと)の経過は、毎回ログに出る。語句を覚えたときの投稿以外に、動いているかを知る手がかりになる。

```
[keyword]: Learn: 87 notes (9 bot notes skipped), 12 keywords (3 not yet learned: 1 proper, 2 common)   投稿87件(ほかに Bot の投稿9件は除いた)から覚えられる語12語。うち3語はまだ覚えていない(固有名詞1、普通名詞2)
[keyword]: Learned: "ずんだもん" (proper)                                         新しく覚えた(「覚えました」を投稿する)。proper は固有名詞、common は普通名詞
```

- `Learn:` の行が、15〜45分おきに出ていれば、タスクは動いている(次の学習までの間隔は `Next learn in 17.3 min` のように出る)。出ていなければ、`Installing keyword module` と、コンテナの再起動を確認する。
- 覚える語は、見かけた語のうち**まだ覚えていない語**の中から1つ選ぶ(選び方は上の「覚える語の選び方」)。
  すでに覚えている語は選ばないので、`not yet learned` が1以上なら、その回は必ず1語覚える。
- 「`0 keywords`」なら、タイムラインに覚えられる語がなかった(または解析に失敗している)。
  「`(0 not yet learned)`」なら、見かけた語がすべて覚えている語だったので、その回は何も覚えない(`Learned:` の行は出ない)。

### 忘れる

覚えてから30日を過ぎた語句を、1日ごとに5%の確率で忘れる(平均の寿命は約50日)。
語句が増え続けると、新しく覚えた語句が埋もれるため。

- 忘れる処理は、日付が変わったときに1日1回だけ行う(おみくじの結果が1日の途中で変わらないように)。
- 忘れた語句は、また見かければ覚え直す。
- 日数と確率は `src/modules/keyword/index.ts` の `FORGET_AFTER_DAYS` / `FORGET_RATE`。
- 忘れる処理が動くたび(日付が変わったとき、1日1回)、結果をログに出す。忘れた語がなくても出る。

  ```
  [keyword]: Forget: 12 forgotten of 4500 older than 30 days, 9000 remain (e.g. 東京, ずんだ, ...)
  [keyword]: Forget: skipped on the first run          機能を入れた初日だけ
  ```

### 管理コマンドと日次レポート(マスター専用)

`config.json` の `master` のユーザー(このサーバのローカルユーザー)だけが使える。メンションで送る。
返事は送った投稿と同じ公開範囲になるので、語句を公開したくないときはダイレクト(指定したユーザーのみ)で送る。

| コマンド | 内容 |
|---|---|
| `/keywords` | 覚えている語句の数と、最近覚えた10個を返す |
| `/forget 語句` | 語句を忘れて、以後も覚えないようにする(語句は完全一致。`「語句」` と括ってもよい)。まだ覚えていない語句にも使える |
| `/unforget 語句` | 覚えないようにした語句を、また覚えられるようにする |
| `/poll` | アンケートを今すぐ投稿する(`poll` モジュール。upstream にあるコマンドを、ローカルのマスターだけに限った) |
| `/nickname …` | マスターのあだ名の設定と、マスターの表示名の変更(下の「マスターのあだ名」の「コマンド」) |

マスターかどうかは、ユーザー名が `master` と同じで、このサーバのユーザー(他のサーバに同じユーザー名の人がいても、マスターにしない)かで判定する
(`src/utils/is-master.ts`)。マスター以外が送ったコマンドには、反応しない。

「覚えないようにした語句」は、`keyword` モジュールのデータ(`data/memory.json`)に保存される。
不適切語句を自動で除外するロジックは入れていないので、気づいたものはこのコマンドで消す。

日付が変わったとき(忘れる処理と同じ)に、マスターへチャットで「覚えた/忘れた/いま覚えている」の個数と、使っている形態素解析を送る。
「覚えた」には、固有名詞と普通名詞の内訳が付く(`kind` を入れる前に覚えた語は、内訳に含まれない)。
マスターが未設定の場合や、チャットを送れなかった場合は、何もせずログに残す。
起動時にも、使っている形態素解析をログに出す(`Morph analyzer: …`)。

`KeywordModule` は `src/index.ts` で `CoreModule` の次に置いている。
コマンドの語句にトークの反応語(「すき」など)が含まれていても、先にコマンドとして処理されるようにするため。

### 今日よく見かけた言葉

毎日のチャートの投稿(`chart`、22時台)に、「今日よく見かけた言葉は「A」「B」…でした！」を添える。

- 学習(平均30分ごと)でグローバルタイムラインから取り出した語句を、出てきた投稿の数で数える。
  1つの投稿に何回出ても1回。同じ投稿が次の学習でも読まれることがあるので、数えた投稿は飛ばす。
- 数えるのは固有名詞だけ(普通名詞は数えない。一般的すぎる語が上位に混ざるため。`src/modules/keyword/token-filter.ts` の `trendKeywordsOf`)。
  人名の除外(姓・名)と `/forget` した語句の除外は、学習と同じ。学習で覚える語の選び方には影響しない。
- チャートを投稿するときに、2投稿以上に出た語句を多い順に5個まで取り出し、数をリセットする。
  該当する語句が無ければ、その行は出さない。メンションで頼まれたチャートには添えない。
- 集計は `data/memory.json`(コレクション `_keyword_trend`)に保存する。共通処理は `src/utils/keyword-trend.ts`。
- チャートが無効(`chartEnabled: false`)のときは、リセットされずに増え続けるので数えない。
- 日本・東京・YouTube のような、毎日出る一般的な語句が上位を占めるようなら、マスターが `/forget 語句` で除外する
  (学習からも外れる)。集計だけから外す仕組みや、普段より多く出た語句を自動で選ぶ仕組みは、いまは入れていない。

### 使われる場所

共通処理は `src/utils/gen-item-with-keyword.ts`。
`genItemWithKeyword()` は、30%(`KEYWORD_RATE`)の確率で学習した語句を使い、それ以外は従来の `genItem()` を使う。
学習した語句は、10文字(`KEYWORD_MAX_LENGTH`)以下のものだけを使い、8割の確率で接頭辞(「伝説の」など)を付ける。

| 機能 | 使い方 |
|---|---|
| あだ名(`talk`) | 提案するあだ名に使う |
| アンケート(`poll`) | 選択肢に使う。学習した語句が4つ以上あれば、2割の確率で「最近覚えた言葉」だけのアンケートにする(新しい20語から重複なしで4つ) |
| おみくじ(`fortune`) | ラッキーアイテムに使う。候補は**その日の0時より前に覚えた語句だけ**にして、同じ日は同じ結果になるようにしている |
| 独り言(`noting`) | 「〇〇、欲しいなぁ...」など、アイテムを使う独り言(3種)に使う。独り言のうち30%がこの3種から選ばれる(下の「独り言の頻度と選び方」) |
| 「何覚えた？」(`talk`) | 新しく覚えた順に3つ答える(長さの制限なし) |

引き継ぎコード(`friend.ts`)は `genItem()` のまま。学習した語句を混ぜると、推測しやすくなるため。

### 独り言の頻度と選び方

- 10分ごとに、15%(`POST_RATE`)の確率で投稿する。1日に平均21.6件(以前は10%で14.4件)。
- 選び方(`src/modules/noting/pick-note.ts`): まず、アイテムを使うテンプレート(3種)から選ぶかを、30%(`KEYWORD_NOTE_RATE`)の確率で決める。
  そのあと、選んだ側の中から等しい確率で選ぶ。残りの70%は、固定のセリフ(75種)から選ぶ。
  以前は、78種を等しい確率で選んでいたので、アイテムを使うテンプレートは約4%(3/78)しか選ばれなかった。
- 固定のセリフが同じものになる間隔は、平均で約5日に1回(1日に平均15.1件を75種から選ぶ)。以前(約5.4日に1回)と同じくらいに保っている。
- アイテムを使うテンプレートでも、学習した語句が使われるのは30%(`KEYWORD_RATE`)だけで、残りは従来の語彙。
  学習した語句が文面に出るのは、1日に平均1.9件(以前は0.17件)。

## 定期投稿の時刻(日本標準時)

コンテナを `TZ=Asia/Tokyo` で動かす前提で、コード中の時刻は日本時間で書く([CLAUDE.md](../CLAUDE.md) の「実行環境」)。

| 機能 | 時刻 | upstream からの変更 |
|---|---|---|
| チャート(`chart`) | 22時台 | 23時台から変更 |
| 迷路(`maze`) | 20時台 | 22時台から変更 |
| 絵文字の追加の確認(`checkCustomEmojis`) | 8時台 | 23時台から変更 |

「1日1回」の記録は、その日の日付(`年-月-日`)を残して判定している。日付の区切りは日本時間の 0 時。

## あだ名を呼び名にする(`talk`)

「あだ名」と話しかけると、「〇〇とお呼びしてもいいですか？」と聞く。

- 「はい」「いいよ」「いいね」「いいですね」「うん」「それで」「お願い」「気に入」「OK」「オーケー」なら、そのまま呼び名にする。
- 「いいえ」「ううん」「いや」「やだ」「嫌」「だめ」「やめ」なら、呼び名は変えない(「ううん」は「うん」を含むので、否定を先に判定する)。
  「いいです」は、承諾にも断りにもとれるので、どちらにも入れない。
- それ以外の返信は、待ち受けをやめて普段の会話として扱う。
- **チャットでの提案は、10分たつと、返事を待たない。** チャットは返信先の投稿が無く、その人の次の発言がすべて返事になってしまうため。
  期限内でも、チャットでは、返事の言葉(上の承諾・断り・引き直しの言葉)が文の頭にあるときだけ、返事とみなす(頭の句読点や空白は読み飛ばす)。
  期限切れや、頭に返事の言葉が無いときは、待ち受けをやめて普段の会話として扱う。投稿への返信なら、返信先がはっきりしているので、時間がたっていても返事とみなす。
  待ち受けのデータには、待ち受けた時刻(`at`)を持たせている(無い以前の形のものは、期限切れにしない)。
  制限: 「別の話だけど」のように、引き直しの言葉(「別の」)で始まる発言は、引き直しとみなす。
- 呼び名にできる条件は「〇〇って呼んで」と同じ(10文字以下、記号を含まない)。条件を満たすあだ名が出るまで最大10回考え直す。
  考えつかなかったときは、「思い浮かばない」と答える(`src/modules/talk/nickname.ts`)。

### あだ名はいらない、と言われたとき

あだ名の話の中に、「呼ばないで」「呼ばなくて」「つけないで」「付けないで」「やめて」「やめろ」「いらない」「いらん」「要らない」「不要」「しないで」「使わないで」「禁止」などが入っていたら、
あだ名を提案しない。「わかりました、あだ名はやめて、これからも〇〇とお呼びしますね！」(呼び名が無ければ「あだ名はやめておきますね！」)と答えて、呼び名は変えず、返事も待たない。
「田中さんのあだ名やめて」のように、ほかの人の話でも同じ(`ADANA_REFUSE_WORDS`)。

### 引き直し

提案されたあだ名への返事に、「別の」「ほかの」「他の」「もう一回」「もう一度」「引き直」「やり直」「違うの」「ちがうの」が入っていたら、別のあだ名を提案し直す。

- 「やだ、別のがいい」のように、断る言葉と一緒でも、引き直しとして扱う(引き直しを先に判定する)。
- すでに出したあだ名は、同じやりとりの中では出さない。考えつかなければ、「思い浮かばない」と答えて、待ち受けをやめる。
- 引き直しても、決め方は同じ。「はい」などで決め、「いいえ」などで断る。引き直した提案への返事も、同じように扱う。
- 引き直しの回数に上限はない。待ち受けのデータには、これまでに出したあだ名(`seen`)と、引き直した回数(`rerolls`)を持たせている。
- 提案への返事ではなく、あらためて「別のあだ名」と話しかけた場合は、普通に新しいあだ名を提案する。

### ほかの人のあだ名

「〇〇さんのあだ名」と話しかけると、送った本人ではなく〇〇さんのあだ名を考えて、「〇〇さんのあだ名は、「△△」とかいかがでしょうか？」と提案する。

- **ほかの人とみなすのは、〇〇に敬称(さん・ちゃん・くん・君・様・さま・氏・殿・ちゃま・先輩・せんぱい・先生・せんせい)が付いたときか、メンション(`@bob`)のとき。**
  〇〇は、「の」と「あだ名」(「あだな」「渾名」「あだにゃ」。「アダナ」のようにカタカナでもよい)のあいだの語(20文字まで)。
  「君のあだ名」は、これまでどおり藍(二人称)として扱う。
  敬称もメンションも無い「わたしのあだ名」「田中のあだ名」「このあだ名」「別のあだ名」は、送った本人のあだ名として、これまでどおり「お呼びしてもいいですか？」と聞く。
  一人称は「〇〇さん」と言わないので、一人称のリストは持たない。
- **送った本人の呼び名は変えない。** 提案への返事は待ち受けて、引き直しもできる(「別の」など)が、「はい」でも呼び名は変わらず、「気に入ってもらえてよかったです」と答える。
  待ち受けのデータに、誰のあだ名かを `target` として持たせていて、`target` があれば呼び名を変えない。
- メンションで指定した人は、敬称が無ければ「さん」を付けて返す(「@bob のあだ名」→「bobさんのあだ名は…」)。敬称が付いていれば、そのまま。
- 〇〇が藍なら、「私のあだ名を、私が考えるんですか・・・？」のように、やんわり断る。親愛度で、好き・普通・嫌いの返事を変える。待ち受けはしない。
  藍とみなすのは、二人称(あなた・君・お前など。敬称が無くてもよい)と、藍の名前(藍・あい・アイ・AI)に敬称が付いたもの、
  藍のアカウントのユーザー名へのメンション(「@<藍のユーザー名>」。このサーバーのユーザーのときだけ。ほかのサーバーの同じユーザー名は、ほかの人)。
  「藍のあだ名」「あいのあだ名」は、友達の名前かもしれないので、本人のあだ名として扱う。
- 返信にメンションの「@」やサーバー名を残さない(「@bob@example.com のあだ名」→「bobのあだ名」)。返信で、その人に通知が届かないようにするため。
- 「@bob さんのあだ名」のように、メンションと敬称のあいだに空白(全角も)があっても、ひとまとまり(「bobさん」)として拾う。
- 〇〇の頭の呼びかけ(ねえ・ねえねえ・ところで・ちょっと・じゃあ・えっと・おい・そういえば・ちなみに・それと・それから)と、一人称の「の」(私の・僕の・俺の・うちの など)は、名前に含めない
  (「ねえ田中さんのあだ名」→「田中さん」、「私の友達の田中さんのあだ名」→「友達の田中さん」)。外すと敬称だけになるもの(「ねえさん」「おいちゃん」)は、名前の一部として外さない。
  一人称でない「の」は名前の一部(「鈴木の弟さん」)。
- 自分へのメンション(「@自分 のあだ名」「@自分 さんのあだ名」)は、本人のあだ名として扱う。サーバーが違う同じユーザー名(「@alice@ほかのサーバー」)は、ほかの人。
- 実装は `src/modules/talk/nickname.ts` の `findAdanaTarget()`(〇〇を取り出す)と `parseAdanaTarget()`(本人・藍・ほかの人に分ける)。
  誰のあだ名かが増えるときは、`parseAdanaTarget()` の分類と、`talk/index.ts` の `adana()` の分岐を増やす。

### マスターのあだ名

「マスターのあだ名」のように、〇〇がマスターなら、あだ名を考えてマスターに伝える(または、マスターの呼び名にする)。既定はオフ。設定の一覧は [config.md](config.md)。

```jsonc
// config.json
"masterNicknameNames": ["マスター", "<マスターの呼び名>"], // 〇〇がこれならマスター(複数可。敬称は付いても付かなくてもよい)
"masterNicknameNotify": "mention",  // 伝え方: "off"(既定。呼び名にする設定なら、変えたことをチャットで知らせる)| "mention" | "chat"
"masterNicknameMentionVisibility": "home", // mention のときの公開範囲の上限: "public"(既定。頼まれた投稿のまま)| "home" | "specified"
"masterNicknameUpdateName": true,    // 考えたあだ名を、マスターの呼び名にするか(既定 false)
"masterNicknamePerUserDaily": 1,     // 同じ人が1日に頼める回数(既定 1。0 なら制限しない)
"masterNicknameIntervalMinutes": 180 // マスターに伝える間隔(分。既定 180。0 なら制限しない。以前の masterNicknameIntervalHours(時間)も、分が無ければ使える)
```

- `config.json` の `master` が無いとき、または、伝え方が `off` で呼び名にもしないときは使わない。そのときの「マスターさんのあだ名」は、ほかの人のあだ名として扱う。
  `master` があって使わないときは、敬称の無い「マスターのあだ名」(`masterNicknameNames` の名前)も、ほかの人のあだ名として扱う(送った本人のあだ名と取り違えない)。マスター本人が言ったときは、本人のあだ名。
- 〇〇は、`masterNicknameNames` の名前か、`@<master のユーザー名>`(このサーバーのユーザーのときだけ。ほかのサーバーの同じユーザー名は、ほかの人)。
- マスター本人が言ったときは、本人のあだ名として扱う(「お呼びしてもいいですか？」)。
- 提案したら、すぐに伝える(返事は待ち受けない。引き直しもない)。
- 伝え方:
  - `mention`: 頼んだ人の投稿への返信で、マスターにメンションする。公開範囲は、普段の返信と同じく頼んだ人の投稿に合わせるが、
    **`masterNicknameMentionVisibility`(既定は `public` で、上限なし)より広くはしない**(公開で頼まれても、マスターへの公開メンションを出さないようにしたいときは、`home` か `specified` にする)。
    フォロワー限定・ダイレクトなら、頼んだ人とマスターだけのダイレクト投稿にする。チャットで頼まれたときも、チャットの内容が公開されないように、2人だけのダイレクト投稿にする。
    チャットで頼まれたときは、そのダイレクト投稿が頼んだ人のチャットには出ないので、チャットにも「マスターに伝えておきました！」と返す(呼び名にする設定なら「にしてみました！ マスターにも伝えておきました！」)。
    このチャットの返事が失敗しても、マスターには伝え終わっているので、伝えられなかったことにはしない(回数の記録も戻さない)。
  - `chat`: マスターにチャットで伝え、頼んだ人には「マスターに伝えておきました！」と返す(伝え終わってから返すので、過去形)。チャットは相互フォローでないと送れない。
  - `off`(呼び名にする設定のとき): マスターの呼び名を変え、変えたことをマスターにチャットで知らせる。頼んだ人にも、`chat` と同じ返事をする。
    呼び名にしない設定なら、`off` は使わない(「マスターさんのあだ名」は、ほかの人のあだ名になる)。
- 呼び名にする設定なら、伝えられたあとで、マスターの呼び名を変える。決まったことなので、「いかがでしょうか？」とは聞かず、
  「〇〇に頼まれて、マスターの呼び名を「X」にしました！ 戻すときは「〇〇って呼んで」と言ってくださいね」と伝える(メンション・チャットとも、頼んだ人への返事も同じ)。
  呼び名にしない設定では、「マスターのあだ名を考えました！ 「X」とかいかがでしょうか？」と提案する。
- **「〇〇」(頼んだ人)は、「表示名(@ユーザー名)」で書く**(例: 「アリス(@alice)に頼まれて」)。藍が付けた呼び名は、マスターには誰のことか分からないので使わない。
  表示名が無いか、ユーザー名と同じなら「@ユーザー名」だけ。別のサーバーの人は「@ユーザー名@サーバー」。
  表示名は本人が決められるので、絵文字コードを除き、改行を空白にし、メンション・MFM・URL になる記号(`@ $ < > ` * ~ # : \ [ ] ( )`)を全角にして、20文字までに切る(`describeRequester()`)。
- **通知と返事で「マスター」と書く部分は、`masterNicknameNames` の先頭の名前にする**(例: `["ご主人", "マスター"]` なら「ご主人のあだ名を考えました！」)。空なら「マスター」(`masterLabel()`)。
- 荒らし対策: 同じ人は1日(日本時間の0時で区切る)に `masterNicknamePerUserDaily` 回まで。マスターに伝えるのは、誰からの依頼かに関わらず、`masterNicknameIntervalMinutes` 分に1回まで。
  制限にかかったときも、あだ名は考えて返し、「今日はもう伝えたんでした！ また明日」「さっき伝えたばかりでした！ 〇〇からなら、また伝えられます」と添える。
  次に伝えられる時刻は、MFM の `$[unixtime …]` で書く(見る人の時刻で表示される)。
  チャットでも、メンションの投稿と同じ MFM として描画され、時計のアイコンつきで「2026/10/9 1:49:42 (3時間後)」のように表示される(実際の画面で確認済み)。
- 制限の記録は、伝える前に残し、**マスターに伝えられなかったときだけ**元に戻す(同時に頼まれても、制限を超えないため)。そのときは「うまく伝えられませんでした」と答える。
  マスターに伝え終わったあとの、呼び名の変更と、頼んだ人への返事が失敗しても、伝えられなかったことにはしない(ログに残すだけ。記録も戻さない)。
  戻すと、マスターには届いているのに、何度でも頼めてしまうため。呼び名の変更は、頼んだ人への返事より先に行う。頼んだ人の回数は、その人の記録(talk モジュールの `masterNickname`)、
  最後に伝えた時刻は、talk モジュールのデータ(`masterNicknameNotifiedAt`)に置く。
- 実装は `src/modules/talk/master-nickname.ts`(設定の解釈と制限の判定)と、`talk/index.ts` の `adanaForMaster()`。
  設定(コマンドで変えた値を含む)は、`masterNickname` モジュール(`src/modules/master-nickname/`)から取る。

#### コマンド(`/nickname`)

マスター本人だけが使える(メンションかチャット。表示名の変更のコマンドは、許可の URL などを含むのでチャットだけ)。
コマンドで変えた設定は、`masterNickname` モジュールのデータに残り、**`config.json` の値より優先する**(再起動しても残る)。`config.json` は初期値の役割になる。

| コマンド | 内容 |
|---|---|
| `/nickname status` | 今の設定と、表示名の変更の状態(オンオフ、方式、許可の検証の結果、承認待ち、変える前の名前) |
| `/nickname on` / `off` | マスターのあだ名を使うか |
| `/nickname notify off\|mention\|chat` | 伝え方(`masterNicknameNotify`) |
| `/nickname callname on\|off` | 考えたあだ名を、藍が呼ぶ呼び名にするか(`masterNicknameUpdateName`) |
| `/nickname visibility public\|home\|specified` | メンションの公開範囲の上限(`masterNicknameMentionVisibility`) |
| `/nickname daily <回数>` / `interval <分>` | 同じ人の1日の回数と、マスターに伝える間隔(0 で制限しない) |
| `/nickname reset` | コマンドで変えた設定を消して、`config.json` の値に戻す |
| `/nickname rename on` / `off` | 表示名の変更を使うか(**初期状態はオフ**) |
| `/nickname rename mode approval\|immediate` | 承認してから変えるか、すぐ変えるか |
| `/nickname rename setup` | 許可(MiAuth)の URL を出す |
| `/nickname rename check` | 許可(トークン)を、もう一度確かめる |
| `/nickname rename revert` | 表示名を、最初に変える前の名前に戻す |
| `/nickname rename forget` | 許可(トークン)を消して、オフにする(Misskey の設定の「連携」からも取り消す) |

コマンドは、トークなどの反応より先に処理する(`src/index.ts` で、`MasterNicknameModule` を `TalkModule` より前に置いている)。

#### マスターの表示名を変える

「マスターのあだ名」と頼まれたら、考えたあだ名で、マスターの Misskey の表示名を**丸ごと置き換える**。既定はオフで、2段階でオンにする。

1. `config.json` の `masterRenameEnabled` を `true` にする(使えるようにするだけ)。
2. マスターがチャットで `/nickname rename setup` と送り、出てきた URL で許可する。藍が、許可(トークン)を受け取って確かめる。
3. `/nickname rename on` でオンにする。

- **許可(MiAuth)**: 求める権限は `read:account`(本人の確認)と `write:account`(表示名の変更)だけ。許可を受け取るまで、5秒おきに、最長10分待つ。
  トークンは `masterNickname` モジュールのデータ(`data/memory.json`)に残す。ログには出さない。
- **許可の検証**(起動のたびと、受け取ったとき・`check` のとき)。次のどれかなら、**表示名の変更だけを止めて**(藍の本体は動く)、理由をログに残し、マスターにチャットで知らせる(同じ理由は1回だけ)。
  - 持ち主がマスター本人でない(このサーバーの、`master` のユーザーでない)
  - ブラウザのログインのトークン(secure な API の `i/apps` が通る。すべての権限を持つ)
  - `read:account`・`write:account` が無い、またはそれ以外の権限が1つでもある
  - 権限の一覧が取れない、調べた結果が分からない(レート制限など。安全のため止める)
  - 表示名を変えるときに、トークンが使えないエラー(`PERMISSION_DENIED`・`AUTHENTICATION_FAILED` など)が返った
- **権限の調べ方**(`token-check.ts`): Misskey の API は「secure の確認 → レート制限 → 権限の確認 → パラメーターの検査 → 処理」の順で動く。
  サーバーの `/api.json` から、権限ごとに API を1つ選び、型の違う値(object)をわざと送る。権限が無ければ `PERMISSION_DENIED`、あれば `INVALID_PARAM` になり、どちらでも処理は動かない。
  型のあるプロパティが無い API しかない権限は、読み取りなら実際に呼び(読むだけ)、書き込みなら調べない(Misskey 2026.10.0 では `write:admin:drive` だけ。MiAuth で発行するので、付くことはない)。
  権限の一覧はサーバーから取るので、Misskey が更新されて権限が増えても、調べる対象に入る。
- **承認(既定)**: マスターにチャットで「〇〇に頼まれて、…表示名を「X」に変えてもいいですか？」と聞き、`masterRenameApprovalMinutes`(既定 60)分以内の「はい」で変える。
  「いいえ」なら変えない。期限を過ぎた返事には「取り消しました」と答える。返事は、チャットの文の頭の「はい」「いいえ」などで見分ける(ほかの発言は、普段の反応に回す)。
  承認を待っている間の依頼は、表示名は聞かず、通常の連絡(伝え方の設定どおり)にする。承認の結果は、頼んだ人には知らせない。
- **すぐ変える**(`masterRenameMode: immediate` か `/nickname rename mode immediate`): すぐ変えて、マスターにチャットで知らせる。頼んだ人にも「表示名も変えておきました」と返す。
- 表示名を変える設定のときは、マスターへの連絡は、承認の問いかけ(または変えたことの知らせ)にまとめる(伝え方の設定より優先)。回数・間隔の制限は、通常と同じ。
  表示名を変えられなかったときは、通常と同じく回数の記録を戻し、「伝えられませんでした」と答える。
- 呼び名にする設定(`callname`)なら、表示名を変えたときに、藍の中のマスターの呼び名も変える。
- 最初に変える前の表示名を残し、`/nickname rename revert` で戻す(表示名が無かったときは、無い状態に戻す)。
- 実装は `src/modules/master-nickname/`(`index.ts`: コマンド・承認・表示名の変更、`commands.ts`: コマンドの解釈、`token-check.ts`: 許可の検証、`miauth.ts`: 許可の受け取り)。

## 親愛度

リバーシ(upstream)と同じく、ゲームで遊ぶと親愛度が上がる。どれも1日1回まで。

| ゲーム | 上がる条件 |
|---|---|
| 数取り(`kazutori`) | 勝ったとき |
| 数当て(`guessing-game`) | 正解したとき |

親愛度は、挨拶などの反応や誕生日のお祝い(親愛度3以上)に影響する。
1日1回の判定は、`src/utils/inc-love-once-a-day.ts` の `incLoveOncePerDay()` で行う(記録は、モジュールごとのデータの `lastWonAt`)。

## 返信の公開範囲

メンションへの返信は、話しかけた投稿と同じ公開範囲にする(`src/message.ts`)。upstream は、いつも公開で返す。

| 話しかけた投稿 | 返信 |
|---|---|
| 公開 | 公開 |
| ホーム | ホーム |
| フォロワー限定 | ダイレクト(話しかけた人だけ)。藍がその人にフォローされているとは限らないため |
| ダイレクト | ダイレクト(話しかけた人だけ。ほかの宛先は含めない) |

## リマインダー(`reminder`)

upstream のリマインダー(`remind 〇〇` / `todo 〇〇`)を、次のように変えている。

- 催促の間隔を、12時間から **24時間** にした。
- 催促の回数で、言い方を変える。催促には `#remAInder` を付ける。

  | 催促の回数 | 言い方 |
  |---|---|
  | 1〜7回目 | 「これやりましたか？」 |
  | 8〜30回目(1週間) | 「もうやりましたよね？？」 |
  | 31回目〜(1ヶ月) | 「まだやってないんですか」 |
  | 61回目〜(2ヶ月) | 10% の確率で「なに言おうとしたんでしたっけ」と忘れて、リマインダーを消す。それ以外は1ヶ月と同じ |

- 引用だけのリマインダーで、引用元が消されていたら、催促できないので、リマインダーを消す(upstream と同じ考え。
  `2.0.1-mk3.4.3` より前は、got のエラーの見方が違っていて、消されずに止まったまま残っていた)。
- チャットで頼まれたリマインダーは、言い方を変えない(upstream のまま)。

## リバーシの強さ

対局を頼むときの言葉で、強さを選べる(upstream は「接待」だけ)。何も言わなければ「ふつう」(upstream は「強」)。

| 言葉 | 強さ | 選択画面の名前 | 対局開始の投稿 |
|---|---|---|---|
| 接待 | 0 | 接待 | (接待を始めました) |
| 簡単、かんたん、易しい、やさしい、手加減、easy、やさしく、優しく | 2 | かんたん | やさしい |
| ふつう、普通、normal | 3 | ふつう | ふつう |
