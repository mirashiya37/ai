# 独自機能

upstream(`syuilo/ai`)に対して、このフォークで追加・変更した機能。
バージョンごとの変更は [changelog.md](changelog.md) を参照。

## 学習した語句(キーワード)

`keyword` モジュールが、15〜45分の間隔(平均30分)でグローバルタイムラインのノートを形態素解析して、固有名詞と一部の普通名詞を1つ覚える。
覚えた語句はコレクション `_keyword_learnedKeywords`(`{ keyword, learnedAt, kind }`)に保存される。
`kind` は `proper`(固有名詞)か `common`(普通名詞)。この項目を入れる前に覚えた語にはない。

### 覚える語句

- 固有名詞で、読みがあるもの(辞書にない語や、読みがカタカナでない語は覚えない)。
- 普通名詞は、一般的すぎる語を除いた次のものだけ覚える(`src/modules/keyword/token-filter.ts`)。
  固有名詞の語が埋もれないようにするため。upstream は固有名詞だけ。
  - 細分類が「一般」(「今日」などの副詞可能、「発見」などのサ変可能、助数詞可能は覚えない)。MeCab(IPADIC)では「名詞,一般」。
  - 3文字以上(「天気」「時間」は覚えない)。
  - 英数字だけの語(`site`、`LLM`)と、ひらがなだけの語(「ほんと」「おなか」)は覚えない。
  - 例: 武勇伝、いじめっ子、ジンギスカン、ゴミ箱、リッチテキスト。
  - 固有名詞の語には、この絞り込みをしない(英数字だけの語も覚える)。
- 解析の前に、本文から MFM の記法を取り除く(`mfm-js` で構文木にして、文字だけを取り出す。`src/modules/keyword/strip-mfm.ts`)。
  `tada` などの関数名、`https` やドメイン・パスの一部、絵文字名の一部(`meow` など)が、固有名詞と判定されるため。
  - 取り除く: URL、メンション(`@user@host`)、カスタム絵文字(`:meow_sushi:`、`:name@host:`)と Unicode 絵文字、
    コード(`` ` ``、```` ``` ````)、数式、引用(`>`)、関数の名前と引数(`$[spin.speed=1s …]` の `spin.speed=1s`)、`unixtime`。
  - 残す: 装飾(`**` `~~` `<small>` `<center>` `<i>` と `$[…]`)の中の文字、リンクの表示名(`[表示名](URL)`)、
    ハッシュタグ(`#` を外して中身)、`<plain>` の中身(MFM として解釈しない文字なので、そのまま)、検索(`語 [検索]`)の語、`ruby` の親文字(ふりがなは除く)。
  - 閉じていない MFM(`$[tada 閉じてない`)は、パーサーが全体をただの文字として返す。このときも、関数の開き(`$[tada `)と装飾のタグ(`<small>`)は取り除く。
  - 取り除いた部分は空白にして、前後の語がつながらないようにする。時刻の `12:30:45` は絵文字の記法とみなさず、残す。
  - すでに覚えた語は、この処理では消えない。MFM の名残の語は、`/forget 語句` で消す。
  - 本文に単語として書かれた `https` や `URL` は残るので、気になれば `/forget` で除外する。
- Bot アカウント(プロフィールで Bot にしているアカウント)の投稿は、学習にも「今日よく見かけた言葉」にも使わない(`src/modules/keyword/note-filter.ts`)。
  地震速報や定型文の返信のような Bot の連投が、同じ語として大量に混ざるため。Bot の設定をしていないアカウントは見分けられない。
  すでに覚えた語は、この処理では消えない。気づいた語は `/forget 語句` で消す。
- 解析に渡す投稿は、1件5000文字まで(超えた分は切り捨てる)。他のサーバーの長い投稿が1件混ざるだけで、Sudachi が全体をエラーにするため
  (詳しくは [morph-analyzer.md](morph-analyzer.md) の「注意点」)。
- 人名は、名字・名前だけのもの(細分類が「姓」「名」)を覚えない。
  キャラクター名(例: 初音ミク)や、辞書にフルネームで載っている有名人の名前(細分類が「一般」)は覚える。
  一般の人の名前は辞書に載っていないため、名字と名前に分かれて除外される。
- 形態素解析は MeCab と Sudachi を選べる。詳しくは [morph-analyzer.md](morph-analyzer.md)。

### 学習の間隔

次の学習までの間隔は、毎回、15〜45分から一様に選んで引き直す(平均は30分。`src/modules/keyword/learn-interval.ts`)。
投稿が、いつも同じ間隔で並ばないようにするため。

- 1日に学習する回数は、平均48回(これまでの30分固定と同じ)。
- 学習が失敗しても、次の予約は続く(エラーは、これまでどおり外に出る)。
- 起動してから最初の学習も、同じ範囲の間隔で行う。
- 平均を30分より短くしたいときは、一様ではなく、短い間隔に偏った分布が要る
  (15〜45分を一様に選ぶと、平均は真ん中の30分になるため)。

### 覚える語の選び方

見かけた語のうち、まだ覚えていない語の中から、1回に1語を選ぶ(`src/modules/keyword/pick-candidate.ts`)。

1. まず、固有名詞と普通名詞のどちらから選ぶかを、**固有名詞を60%** の確率で決める。選んだほうに候補がなければ、もう一方から選ぶ。
2. 選んだ側の中から、長い語が選ばれやすいように選ぶ(同じ語が何度も出ていれば、その分選ばれやすい)。

- 確率は `config.json` の `keywordProperRate`(0〜1、未指定なら 0.6)。反映には、Bot の再起動が要る。
- 以前は種類を区別せず、固有名詞が選ばれる割合は、タイムラインの実測で約35%だった(候補の約30%が固有名詞)。
- 候補の数は、100件ごとに、固有名詞が約11語、普通名詞が約25語。固有名詞の候補が空になることはほとんどないので、実際の割合も設定に近い。
- 割合は、ログ(下)と、日次レポートの内訳で確かめる。

### 学習の経過(ログ)

学習(15〜45分ごと)の経過は、毎回ログに出る。語句を覚えたときの投稿以外に、動いているかを知る手がかりになる。

```
[keyword]: Learn: 87 notes (9 bot notes skipped), 12 keywords (3 not yet learned: 1 proper, 2 common)   投稿87件(ほかに Bot の投稿9件は除いた)から覚えられる語12語。うち3語はまだ覚えていない(固有名詞1、普通名詞2)
[keyword]: Learned: "ずんだもん" (proper)                                         新しく覚えた(「覚えました」を投稿する)。proper は固有名詞、common は普通名詞
```

- `Learn:` の行が、15〜45分おきに出ていれば、タスクは動いている(次の学習までの間隔は `Next learn in 17.3 min` のように出る)。出ていなければ、`Installing keyword module` と、コンテナの再起動を確認する。
- 覚える語は、見かけた語のうち**まだ覚えていない語**の中から1つ選ぶ(選び方は上の「覚える語の選び方」)。
  すでに覚えている語は選ばないので、`not yet learned` が1以上なら、その回は必ず1語覚える。
- 「`0 keywords`」なら、タイムラインに覚えられる語がなかった(または解析に失敗している)。
  「`(0 not yet learned)`」なら、見かけた語がすべて覚えている語だったので、その回は何も覚えない(`Learned:` の行は出ない)。

### 忘れる

覚えてから30日を過ぎた語句を、1日ごとに5%の確率で忘れる(平均の寿命は約50日)。
語句が増え続けると、新しく覚えた語句が埋もれるため。

- 忘れる処理は、日付が変わったときに1日1回だけ行う(おみくじの結果が1日の途中で変わらないように)。
- 忘れた語句は、また見かければ覚え直す。
- 日数と確率は `src/modules/keyword/index.ts` の `FORGET_AFTER_DAYS` / `FORGET_RATE`。
- 忘れる処理が動くたび(日付が変わったとき、1日1回)、結果をログに出す。忘れた語がなくても出る。

  ```
  [keyword]: Forget: 12 forgotten of 4500 older than 30 days, 9000 remain (e.g. 東京, ずんだ, ...)
  [keyword]: Forget: skipped on the first run          機能を入れた初日だけ
  ```

### 管理コマンドと日次レポート(マスター専用)

`config.json` の `master` のユーザー(このサーバのローカルユーザー)だけが使える。メンションかチャットで送る(`/nickname` はチャットだけ)。
メンションの返事は送った投稿と同じ公開範囲になるので、語句を公開したくないときはダイレクト(指定したユーザーのみ)かチャットで送る。

| コマンド | 内容 |
|---|---|
| `/keywords` | 覚えている語句の数と、最近覚えた10個を返す |
| `/forget 語句` | 語句を忘れて、以後も覚えないようにする(語句は完全一致。`「語句」` と括ってもよい)。まだ覚えていない語句にも使える |
| `/unforget 語句` | 覚えないようにした語句を、また覚えられるようにする |
| `/poll` | アンケートを今すぐ投稿する(`poll` モジュール。upstream にあるコマンドを、ローカルのマスターだけに限った) |
| `/nickname …` | マスターのあだ名の設定と、マスターの表示名の変更(**チャットだけ**。[nickname.md](nickname.md) の「コマンド」) |

マスターかどうかは、ユーザー名が `master` と同じで、このサーバのユーザー(他のサーバに同じユーザー名の人がいても、マスターにしない)かで判定する
(`src/utils/is-master.ts`)。マスター以外が送ったコマンドには、反応しない。

「覚えないようにした語句」は、`keyword` モジュールのデータ(`data/memory.json`)に保存される。
不適切語句を自動で除外するロジックは入れていないので、気づいたものはこのコマンドで消す。

日付が変わったとき(忘れる処理と同じ)に、マスターへチャットで「覚えた/忘れた/いま覚えている」の個数と、使っている形態素解析を送る。
「覚えた」には、固有名詞と普通名詞の内訳が付く(`kind` を入れる前に覚えた語は、内訳に含まれない)。
マスターが未設定の場合や、チャットを送れなかった場合は、何もせずログに残す。
起動時にも、使っている形態素解析をログに出す(`Morph analyzer: …`)。

`KeywordModule` は `src/index.ts` で `CoreModule` の次に置いている。
コマンドの語句にトークの反応語(「すき」など)が含まれていても、先にコマンドとして処理されるようにするため。

### 今日よく見かけた言葉

毎日のチャートの投稿(`chart`、22時台)に、「今日よく見かけた言葉は「A」「B」…でした！」を添える。

- 学習(平均30分ごと)でグローバルタイムラインから取り出した語句を、出てきた投稿の数で数える。
  1つの投稿に何回出ても1回。同じ投稿が次の学習でも読まれることがあるので、数えた投稿は飛ばす。
- 数えるのは固有名詞だけ(普通名詞は数えない。一般的すぎる語が上位に混ざるため。`src/modules/keyword/token-filter.ts` の `trendKeywordsOf`)。
  人名の除外(姓・名)と `/forget` した語句の除外は、学習と同じ。学習で覚える語の選び方には影響しない。
- チャートを投稿するときに、2投稿以上に出た語句を多い順に5個まで取り出し、数をリセットする。
  該当する語句が無ければ、その行は出さない。メンションで頼まれたチャートには添えない。
- 集計は `data/memory.json`(コレクション `_keyword_trend`)に保存する。共通処理は `src/utils/keyword-trend.ts`。
- チャートが無効(`chartEnabled: false`)のときは、リセットされずに増え続けるので数えない。
- 日本・東京・YouTube のような、毎日出る一般的な語句が上位を占めるようなら、マスターが `/forget 語句` で除外する
  (学習からも外れる)。集計だけから外す仕組みや、普段より多く出た語句を自動で選ぶ仕組みは、いまは入れていない。

### 使われる場所

共通処理は `src/utils/gen-item-with-keyword.ts`。
`genItemWithKeyword()` は、30%(`KEYWORD_RATE`)の確率で学習した語句を使い、それ以外は従来の `genItem()` を使う。
学習した語句は、10文字(`KEYWORD_MAX_LENGTH`)以下のものだけを使い、8割の確率で接頭辞(「伝説の」など)を付ける。

| 機能 | 使い方 |
|---|---|
| あだ名(`talk`) | 提案するあだ名に使う |
| アンケート(`poll`) | 選択肢に使う。学習した語句が4つ以上あれば、2割の確率で「最近覚えた言葉」だけのアンケートにする(新しい20語から重複なしで4つ) |
| おみくじ(`fortune`) | ラッキーアイテムに使う。候補は**その日の0時より前に覚えた語句だけ**にして、同じ日は同じ結果になるようにしている |
| 独り言(`noting`) | 「〇〇、欲しいなぁ...」など、アイテムを使う独り言(3種)に使う。独り言のうち30%がこの3種から選ばれる(下の「独り言の頻度と選び方」) |
| 「何覚えた？」(`talk`) | 新しく覚えた順に3つ答える(長さの制限なし) |

引き継ぎコード(`friend.ts`)は `genItem()` のまま。学習した語句を混ぜると、推測しやすくなるため。

### 独り言の頻度と選び方

- 10分ごとに、15%(`POST_RATE`)の確率で投稿する。1日に平均21.6件(以前は10%で14.4件)。
- 選び方(`src/modules/noting/pick-note.ts`): まず、アイテムを使うテンプレート(3種)から選ぶかを、30%(`KEYWORD_NOTE_RATE`)の確率で決める。
  そのあと、選んだ側の中から等しい確率で選ぶ。残りの70%は、固定のセリフ(75種)から選ぶ。
  以前は、78種を等しい確率で選んでいたので、アイテムを使うテンプレートは約4%(3/78)しか選ばれなかった。
- 固定のセリフが同じものになる間隔は、平均で約5日に1回(1日に平均15.1件を75種から選ぶ)。以前(約5.4日に1回)と同じくらいに保っている。
- アイテムを使うテンプレートでも、学習した語句が使われるのは30%(`KEYWORD_RATE`)だけで、残りは従来の語彙。
  学習した語句が文面に出るのは、1日に平均1.9件(以前は0.17件)。

## 定期投稿の時刻(日本標準時)

コンテナを `TZ=Asia/Tokyo` で動かす前提で、コード中の時刻は日本時間で書く([CLAUDE.md](../CLAUDE.md) の「実行環境」)。

| 機能 | 時刻 | upstream からの変更 |
|---|---|---|
| チャート(`chart`) | 22時台 | 23時台から変更 |
| 迷路(`maze`) | 20時台 | 22時台から変更 |
| 絵文字の追加の確認(`checkCustomEmojis`) | 8時台 | 23時台から変更 |

「1日1回」の記録は、その日の日付(`年-月-日`)を残して判定している。日付の区切りは日本時間の 0 時。

## 絵文字の追加の確認(`checkCustomEmojis`)

毎朝8時台と、「カスタム絵文字チェック」とメンションされたときに、追加された絵文字を投稿する(`checkEmojisEnabled`)。
最後に投稿した絵文字のIDを記憶に残し、それより新しいものを調べる。

- 初回(IDの記憶がない)は、新しい順に5件を取り、古い順に並べて投稿する。
- 2回目以降は、新着を100件ずつ全件取る(最大10回=1000件。残りは次の回に続けて取る)。「◯件追加されました！」の件数は、取得した全件数。
- 個別投稿(既定)は、概要1件と、絵文字ごとの1件を投稿する。
- まとめ投稿(`checkEmojisAtOnce`)は、`checkEmojisChunkSize` 件(既定 20)ごとに複数のノートに分ける。1ノート目に概要、2ノート目以降は `(2/3)` のようなページ表記を付ける。
  1ノートが 3000 字を超えるときは、さらに分ける。
  2ノート目以降は、直前のノートへの返信としてつなげる(2ノート目は1ノート目へ、3ノート目は2ノート目へ)。
- ノートの間は1秒空ける。最後のIDは、すべて投稿してから記憶する(途中で失敗したときは記憶せず、次の回に最初からやり直す)。
- 絵文字の一覧を取れなかったときは、権限が足りない(401・403)か、それ以外のエラーかで文を分ける。頼まれたときは頼んだ人に返事をし、
  定期の確認ではマスターにチャットで知らせる(公開の投稿はしない。マスターが未設定か、チャットが送れないときは、ログに残すだけ)。

## あだ名(`talk`・`masterNickname`)

「あだ名」と話しかけると、あだ名を考えて提案する。本人のあだ名は「はい」で呼び名にし、ほかの人・藍・マスターのあだ名にも答える。
マスターのあだ名は、マスターに伝えたり、マスターの表示名を変えたりできる(既定はオフ)。マスターは `/nickname` コマンドで設定を変えられる。

全体の流れ、判定の条件、設定、データの置き場所、既知の制限は [nickname.md](nickname.md) にまとめている。

## 親愛度

リバーシ(upstream)と同じく、ゲームで遊ぶと親愛度が上がる。どれも1日1回まで。

| ゲーム | 上がる条件 |
|---|---|
| 数取り(`kazutori`) | 勝ったとき |
| 数当て(`guessing-game`) | 正解したとき |

親愛度は、挨拶などの反応や誕生日のお祝い(親愛度3以上)に影響する。
1日1回の判定は、`src/utils/inc-love-once-a-day.ts` の `incLoveOncePerDay()` で行う(記録は、モジュールごとのデータの `lastWonAt`)。

## 返信の公開範囲

メンションへの返信は、話しかけた投稿と同じ公開範囲にする(`src/message.ts`)。upstream は、いつも公開で返す。

| 話しかけた投稿 | 返信 |
|---|---|
| 公開 | 公開 |
| ホーム | ホーム |
| フォロワー限定 | ダイレクト(話しかけた人だけ)。藍がその人にフォローされているとは限らないため |
| ダイレクト | ダイレクト(話しかけた人だけ。ほかの宛先は含めない) |

| ごめん | ごめん、ゴメン、sorry | -3以下だけ | confused |
| 抱っこ | だっこ、抱っこ | 5以上 / -3以下 | |
| 脱いで | 脱げ、脱いで、ぬげ、ぬいで | -3以下だけ | confused |
| できる | できる、出来る | なし | 🙌 |

- 「5以上 / -3以下」は、親愛度が5以上なら好きの返事、-3以下なら嫌いの返事、そのあいだは普通の返事にする、という意味。
  多くの反応がこの境目で、`src/modules/talk/by-love.ts` の `byLove()` の既定値になっている。違う境目の反応は、太字にした。
- 「ありがとう」は、`2.0.1-mk3.4.2` より前は、嫌いの返事の境目が「3以下」になっていて、ほとんどの人に嫌いの返事をしていた。

## リマインダー(`reminder`)

upstream のリマインダー(`remind 〇〇` / `todo 〇〇`)を、次のように変えている。

- 催促の間隔を、12時間から **24時間** にした。
- 催促の回数で、言い方を変える。催促には `#remAInder` を付ける。

  | 催促の回数 | 言い方 |
  |---|---|
  | 1〜7回目 | 「これやりましたか？」 |
  | 8〜30回目(1週間) | 「もうやりましたよね？？」 |
  | 31回目〜(1ヶ月) | 「まだやってないんですか」 |
  | 61回目〜(2ヶ月) | 10% の確率で「なに言おうとしたんでしたっけ」と忘れて、リマインダーを消す。それ以外は1ヶ月と同じ |

- 引用だけのリマインダーで、引用元が消されていたら、催促できないので、リマインダーを消す(upstream と同じ考え。
  `2.0.1-mk3.4.3` より前は、got のエラーの見方が違っていて、消されずに止まったまま残っていた)。
- チャットで頼まれたリマインダーは、言い方を変えない(upstream のまま)。

## リバーシの強さ

対局を頼むときの言葉で、強さを選べる(upstream は「接待」だけ)。何も言わなければ「ふつう」(upstream は「強」)。

| 言葉 | 強さ | 選択画面の名前 | 対局開始の投稿 |
|---|---|---|---|
| 接待 | 0 | 接待 | (接待を始めました) |
| 簡単、かんたん、易しい、やさしい、手加減、easy、やさしく、優しく | 2 | かんたん | やさしい |
| ふつう、普通、normal | 3 | ふつう | ふつう |
| 難しい、むずかしい、死、鬼、地獄、hard、つよい、強い、強く、つよく | 4 | むずかしい | つよい |
| 「藍」と「本気」の両方 | 5 | 藍の本気 | 藍の本気 |

- **選択画面の名前は相手(遊ぶ人)から見た難しさ、対局開始の投稿は藍から見た強さ**で書いている。表記が違うのは意図したもの。
- 対局の投稿には `#aiReversi` を付ける。
