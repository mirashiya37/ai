# あだ名

「あだ名」と話しかけたときの動き。`talk` モジュール(提案・返事・マスターへの連絡)と、`masterNickname` モジュール(マスター用のコマンドと、マスターの表示名の変更)で受け持つ。
設定の項目の一覧は [config.md](config.md)、テストは [testing.md](testing.md)。

## 全体の流れ

メンションかチャットに「あだな」「あだ名」「渾名」「あだにゃ」(カタカナでもよい)が入っていると反応する(`talk` の `adana()`)。

1. 「呼ばないで」「やめて」「いらない」などが入っていたら、あだ名を提案しない([あだ名はいらない、と言われたとき](#あだ名はいらないと言われたとき))。
2. 「〇〇のあだ名」の〇〇から、誰のあだ名かを決める([誰のあだ名か](#誰のあだ名か)、`parseAdanaTarget()`)。
3. 決めた相手ごとに答える。

| 相手 | 例 | 答え方 | 返事を待つか |
|---|---|---|---|
| 送った本人 | 「あだ名」「わたしのあだ名」「田中のあだ名」 | 「〇〇、「X」とお呼びしてもいいですか？」。「はい」で呼び名にする | 待つ |
| ほかの人 | 「田中さんのあだ名」「@bob のあだ名」 | 「田中さんのあだ名は、「X」とかいかがでしょうか？」。呼び名は変えない | 待つ |
| 藍 | 「あなたのあだ名」「藍ちゃんのあだ名」 | 親愛度に合わせて、やんわり断る | 待たない |
| マスター | 「マスターのあだ名」(呼び名にする設定か、表示名の変更がオンのとき) | 呼び名を変えたことを、マスターに伝える。表示名を変える設定なら、承認を求めるか、すぐ変える。どちらも使わないときは、ほかの人と同じ提案 | 待たない(承認はマスターの返事を待つ)。ほかの人と同じ提案のときは待つ |

あだ名は、学習した語句を混ぜて作る(`genItemWithKeyword()`)。呼び名にできる条件は「〇〇って呼んで」と同じ(10文字以下、記号を含まない)で、
条件を満たすものが出るまで最大10回考え直す。考えつかなければ「すみません、いまはあだ名が思い浮かばないです...」と答える(`pickNickname()`)。

## 本人のあだ名と、提案への返事

「〇〇、「X」とお呼びしてもいいですか？」と聞いて、返事を待つ。

- 「はい」「いいよ」「いいね」「いいですね」「うん」「それで」「お願い」「気に入」「OK」「オーケー」なら、呼び名にする。
- 「いいえ」「ううん」「いや」「やだ」「嫌」「だめ」「やめ」なら、呼び名は変えない(「ううん」は「うん」を含むので、否定を先に判定する)。
  「いいです」は、承諾にも断りにもとれるので、どちらにも入れない。
- それ以外の返事は、待つのをやめて、普段の会話として扱う。
- **チャットでの提案は、10分たつと返事を待たない。** チャットは返信先の投稿が無く、その人の次の発言がすべて返事になってしまうため。
  期限内でも、チャットでは、返事の言葉(承諾・断り・引き直しの言葉)が文の頭にあるときだけ返事とみなす(頭の句読点や空白は読み飛ばす)。
  投稿への返信なら、返信先がはっきりしているので、時間がたっていても返事とみなす。
- マスターが表示名の変更の承認を求められているときは、マスターのチャットの返事を、承認の返事として扱う([承認](#承認既定))。

### 引き直し

返事に「別の」「ほかの」「他の」「もう一回」「もう一度」「引き直」「やり直」「違うの」「ちがうの」が入っていたら、別のあだ名を提案し直す。

- 「やだ、別のがいい」のように、断る言葉と一緒でも、引き直しとして扱う(引き直しを先に判定する)。
- 同じやりとりの中で、すでに出したあだ名は出さない。考えつかなければ「思い浮かばない」と答えて、待つのをやめる。
- 回数に上限はない。引き直した提案への返事も、同じように扱う。
- 提案への返事ではなく、あらためて「別のあだ名」と話しかけた場合は、普通に新しいあだ名を提案する。

### あだ名はいらない、と言われたとき

あだ名の話の中に、「呼ばないで」「呼ばなくて」「呼ぶのをやめ」「つけないで」「付けないで」「やめて」「やめろ」「いらない」「いらん」「要らない」「不要」「しないで」「使わないで」「禁止」が入っていたら、
あだ名を提案しない。「わかりました、あだ名はやめて、これからも〇〇とお呼びしますね！」(呼び名が無ければ「あだ名はやめておきますね！」)と答えて、呼び名は変えず、返事も待たない。
「田中さんのあだ名やめて」のように、ほかの人の話でも同じ(`ADANA_REFUSE_WORDS`)。

## 返信の宛先

あだ名の話への返信(提案・返事・断り・マスターに伝えたという報告など)は、投稿への返信なら、頭に送った人へのメンション(`@ユーザー名`。別のサーバーの人は `@ユーザー名@サーバー`)を付ける
(`src/utils/reply-with-mention.ts`)。チャットには付けない。マスターへの連絡(承認の問いかけなど、チャットのもの)は対象外。

## 誰のあだ名か

〇〇は、「の」と「あだ名」のあいだの語(20文字まで)。次の順に決める(`src/modules/talk/nickname.ts` の `findAdanaTarget()` と `parseAdanaTarget()`)。

| 順 | 〇〇 | 相手 |
|---|---|---|
| 0 | 「〇〇のあだ名」の形でない | 本人 |
| 1 | 自分へのメンション(「@自分 のあだ名」「@自分 さんのあだ名」。ほかのサーバーの同じユーザー名は除く) | 本人 |
| 2 | マスターの名前(`masterNicknameNames`。敬称は問わない)か、`@<master>`(このサーバーのユーザー)。マスターのあだ名を使う設定のときだけ | マスター |
| 3 | マスターのあだ名を使わない設定のときの、マスターの名前(敬称が無くても) | ほかの人 |
| 4 | 二人称(あなた・君・お前 など。敬称が無くてもよい) | 藍 |
| 5 | 敬称もメンションも無い(「わたしのあだ名」「田中のあだ名」「藍のあだ名」) | 本人 |
| 6 | 藍の名前(藍・あい・アイ・AI)に敬称が付いたもの、藍のユーザー名へのメンション(このサーバーのユーザーのときだけ) | 藍 |
| 7 | それ以外(敬称かメンションが付いたもの) | ほかの人 |

- 敬称は、さん・ちゃん・くん・君・様・さま・氏・殿・ちゃま・先輩・せんぱい・先生・せんせい。「君のあだ名」は、二人称として藍。
- 〇〇の頭の呼びかけ(ねえ・ねえねえ・ところで・ちょっと・じゃあ・えっと・おい・そういえば・ちなみに・それと・それから)と、一人称の「の」(私の・僕の・うちの など)は、名前に含めない
  (「ねえ田中さんのあだ名」→「田中さん」、「私の友達の田中さんのあだ名」→「友達の田中さん」)。外すと敬称だけになるもの(「ねえさん」「おいちゃん」)と、一人称でない「の」(「鈴木の弟さん」)は、名前の一部。
- 「@bob さんのあだ名」のように、メンションと敬称のあいだに空白(全角も)があっても、ひとまとまりとして拾う。
- 「藍のあだ名」「あいのあだ名」は、友達の名前かもしれないので、本人のあだ名として扱う。

### ほかの人のあだ名

「〇〇さんのあだ名は、「X」とかいかがでしょうか？」と提案して、返事を待つ。引き直しもできる。
**送った本人の呼び名は変えない**(「はい」でも「気に入ってもらえてよかったです」と答える)。待ち受けのデータの `target` で見分ける。

- 返信には、メンションの「@」とサーバー名を残さない(返信で、その人に通知が届かないようにするため)。敬称が無ければ「さん」を付ける(「@bob@example.com のあだ名」→「bobさんのあだ名は…」)。
- **〇〇は利用者が書いたものなので、返信に入れる前に、メンション・MFM・リンク・ハッシュタグになる記号(`@ $ < > ` * ~ # : \ [ ] ( )`)を全角にする**(`neutralizeMfm()`)。
  「[ここ](https://…)さんのあだ名」なら「［ここ］（https：//…）さんのあだ名は…」と返す。

## マスターのあだ名

〇〇がマスターなら、あだ名を考えて、マスターの呼び名(または表示名)を変え、マスターに知らせる。既定はオフ。
呼び名にも表示名にもしない設定のときは使わず、ほかの人のあだ名と同じ提案になる(下の「使うのは」)。

```jsonc
// config.json
"masterNicknameNames": ["マスター", "<マスターの呼び名>"], // 〇〇がこれならマスター(複数可。敬称は付いても付かなくてもよい)。先頭は、通知や返事でマスターを呼ぶ言い方
"masterNicknameNotify": "mention",  // 伝え方: "off"(既定)| "mention" | "chat"
"masterNicknameMentionVisibility": "home", // mention のときの公開範囲の上限: "public"(既定。頼まれた投稿のまま)| "home" | "specified"
"masterNicknameUpdateName": true,    // 考えたあだ名を、藍の中のマスターの呼び名にするか(既定 false)
"masterNicknamePerUserDaily": 1,     // 同じ人が1日に頼める回数(既定 1。0 なら制限しない)
"masterNicknameIntervalMinutes": 180 // マスターに伝える間隔(分。既定 180。0 なら制限しない)
```

- **使うのは**、`master` があり、`/nickname off` にしていなくて、次のどれかのとき: 呼び名にする(`masterNicknameUpdateName`)、表示名の変更がオンで許可が使える。
  **どちらも使わないときは、マスターには何も起きないので、「マスターのあだ名」「マスターさんのあだ名」は、ほかの人のあだ名として扱う**
  (「〇〇さんのあだ名は、「X」とかいかがでしょうか？」と提案して、返事を待つ。マスターへの連絡はしない。送った本人のあだ名と取り違えない)。
  伝え方(`masterNicknameNotify`)は、呼び名や表示名を変えたことの知らせの送り先だけを決める。「提案だけをマスターに伝える」ことはしない。
- マスター本人が言ったときは、本人のあだ名として扱う(「お呼びしてもいいですか？」)。
- 頼んだ人の返事は待たない(引き直しもない)。考えたら、すぐマスターに伝える。
- 通知と返事で「マスター」と書く部分は、`masterNicknameNames` の先頭の名前(空なら「ご主人様」)。`/nickname` のコマンドの返事(ヘルプ、`status` など)と、許可(トークン)が使えない理由の文も同じ。
- **頼んだ人は「表示名(@ユーザー名)」で書く**(例: 「アリス(@alice)に頼まれて」)。藍が付けた呼び名は、マスターには誰のことか分からないので使わない。
  表示名が無いか、ユーザー名と同じなら「@ユーザー名」だけ。別のサーバーの人は「@ユーザー名@サーバー」。
  表示名は本人が決められるので、絵文字コードを除き、記号を全角にして(`neutralizeMfm()`)、20文字までに切る(`describeRequester()`)。

### 伝え方

| 伝え方 | マスターへ | 頼んだ人へ |
|---|---|---|
| `mention` | 頼んだ人の投稿への返信で、マスターにメンションする(本文の先頭に、頼んだ人のメンションも付ける。通知が届くように) | メンションの投稿が返事(チャットで頼まれたときは、チャットにも「〇〇のあだ名は、「X」にしてみました！ 〇〇にも伝えておきました！」) |
| `chat` | チャットで伝える(相互フォローでないと送れない) | 「〇〇のあだ名は、「X」にしてみました！ 〇〇にも伝えておきました！」 |
| `off` | 呼び名にする設定のときだけ、呼び名を変えたことをチャットで知らせる | `chat` と同じ |

- `mention` の公開範囲は、頼まれた投稿に合わせるが、`masterNicknameMentionVisibility` より広くはしない。フォロワー限定・ダイレクト・チャットで頼まれたときは、頼んだ人とマスターだけのダイレクト投稿。
- 伝えたあとで藍の中のマスターの呼び名を変え、「〇〇に頼まれて、マスターの呼び名を「X」にしました！ 戻すときは「〇〇って呼んで」と言ってくださいね」と伝える(提案ではなく、決まったこととして伝える)。

### 荒らし対策

- 同じ人は1日(日本時間の0時で区切る)に `masterNicknamePerUserDaily` 回まで。マスターに伝えるのは、誰からの依頼かに関わらず `masterNicknameIntervalMinutes` 分に1回まで。
- 制限にかかったときも、あだ名は考えて返し、「今日はもう伝えたんでした！ また明日」「さっき伝えたばかりでした！ 〇〇からなら、また伝えられます」と添える。
  次に伝えられる時刻は、MFM の `$[unixtime …]` で書く(見る人の時刻で表示される。チャットでも、時計のアイコンつきで表示されることを確認済み)。
- 制限の記録は、伝える前に残し、**マスターに伝えられなかったときだけ**元に戻す(同時に頼まれても制限を超えないため)。そのときは「うまく伝えられませんでした」と答える。
  伝え終わったあとの、呼び名の変更と頼んだ人への返事が失敗しても、伝えられなかったことにはしない(何度でも頼めてしまうため)。

## コマンド(`/nickname`)

マスター本人だけが、**チャットで**使える。投稿(メンション)で送ると、「チャットで送ってください」とだけ答えて、何もしない
(返事に設定や承認待ちのあだ名が入り、投稿への返信は公開になることがあるため)。

コマンドで変えた設定は、`masterNickname` モジュールのデータに残り、**`config.json` の値より優先する**(再起動しても残る)。`config.json` は初期値の役割になる。

| コマンド | 内容 |
|---|---|
| `/nickname` / `help` | コマンドの一覧 |
| `/nickname status` | 今の設定と、表示名の変更の状態(オンオフ、方式、許可の検証の結果、承認待ち、変える前の名前、コマンドで変えた項目) |
| `/nickname on` / `off` | マスターのあだ名を使うか |
| `/nickname notify off\|mention\|chat` | 伝え方(`masterNicknameNotify`) |
| `/nickname callname on\|off` | 考えたあだ名を、藍の中の呼び名にするか(`masterNicknameUpdateName`) |
| `/nickname visibility public\|home\|specified` | メンションの公開範囲の上限(`masterNicknameMentionVisibility`) |
| `/nickname daily <回数>` / `interval <分>` | 同じ人の1日の回数と、マスターに伝える間隔(0 で制限しない) |
| `/nickname reset` | コマンドで変えた設定を消して、`config.json` の値に戻す |
| `/nickname rename on` / `off` | 表示名の変更を使うか(**初期状態はオフ**。off にすると、承認待ちも取り消す) |
| `/nickname rename mode approval\|immediate` | 承認してから変えるか、すぐ変えるか |
| `/nickname rename setup` | 許可(MiAuth)の URL を出す |
| `/nickname rename check` | 許可(トークン)を、もう一度確かめる |
| `/nickname rename revert` | 表示名を、最初に変える前の名前に戻す |
| `/nickname rename forget` | 許可(トークン)を消して、オフにする |

コマンドは、トークなどの反応より先に処理する(`src/index.ts` で、`MasterNicknameModule` を `TalkModule` より前に置いている)。

## マスターの表示名を変える

「マスターのあだ名」と頼まれたら、考えたあだ名で、マスターの Misskey の表示名を**丸ごと置き換える**。既定はオフで、次の順にオンにする。

1. `config.json` の `masterRenameEnabled` を `true` にする(使えるようにするだけ)。
2. マスターがチャットで `/nickname rename setup` と送り、出てきた URL で許可する。藍が、許可(トークン)を受け取って確かめる。
3. `/nickname rename on` でオンにする。

### 許可(MiAuth)と検証

- 求める権限は `read:account`(本人の確認)と `write:account`(表示名の変更)だけ。許可を受け取るまで、5秒おきに、最長10分待つ。
- トークンは `masterNickname` モジュールのデータ(`data/memory.json`)に残す。ログには出さない。
- 許可を取り直したときや、`forget` したときも、前の許可は Misskey 側では取り消されない(API では取り消せない)。藍が案内するので、Misskey の設定の「連携」(アクセストークン)から取り消す。
- **検証**(起動のたびと、受け取ったとき・`check` のとき)。次のどれかなら、**表示名の変更だけを止めて**(藍の本体は動く)、理由をログに残し、マスターにチャットで知らせる(同じ理由は1回だけ)。
  - 持ち主がマスター本人でない(このサーバーの、`master` のユーザーでない)
  - ブラウザのログインのトークン(secure な API の `i/apps` が通る。すべての権限を持つ)
  - `read:account`・`write:account` が無い、またはそれ以外の権限が1つでもある(多いときは、先頭の5つと残りの個数を挙げる)
  - 権限の一覧が取れない、調べた結果が分からない(レート制限など。安全のため止める)
  - 表示名を変えるときに、トークンが使えないエラー(`PERMISSION_DENIED`・`AUTHENTICATION_FAILED` など)が返った
- **権限の調べ方**(`token-check.ts`): Misskey の API は「secure の確認 → レート制限 → 権限の確認 → パラメーターの検査 → 処理」の順で動く。
  サーバーの `/api.json` から、権限ごとに API を1つ選び、型の違う値(object)をわざと送る。権限が無ければ `PERMISSION_DENIED`、あれば `INVALID_PARAM` になり、どちらでも処理は動かない。
  型のあるプロパティが無い API しかない権限は、読み取りなら実際に呼び(読むだけ)、書き込みなら調べない(Misskey 2026.10.0 では `write:admin:drive` だけ。MiAuth で発行するので、付くことはない)。
  権限の一覧はサーバーから取るので、Misskey が更新されて権限が増えても、調べる対象に入る。

### 承認(既定)

- マスターにチャットで「〇〇に頼まれて、…表示名を「X」に変えてもいいですか？」と聞き、`masterRenameApprovalMinutes`(既定 60)分以内の「はい」で変える。「いいえ」なら変えない。
  期限を過ぎた返事には「取り消しました」と答える。返事は、チャットの文の頭の「はい」「いいえ」などで見分ける(ほかの発言は、普段の反応に回す)。
- 承認を待つのは1件だけ。聞く前に承認待ちにするので、ほぼ同時に頼まれても2回は聞かない。待っている間の依頼は、表示名は聞かない。呼び名にする設定なら、呼び名を変えた知らせ(伝え方の設定どおり)にする。呼び名にもしない設定なら、マスターには何もせず、ほかの人と同じ提案にする。
- マスターがチャットで自分のあだ名の提案を受けているときでも、承認待ちのあいだの「はい」「いいえ」は、承認の返事として扱う(提案の待ち受けはやめる)。
- 承認の結果は、頼んだ人には知らせない。

### すぐ変える

`masterRenameMode: immediate`(または `/nickname rename mode immediate`)なら、すぐ変えて、マスターに知らせる。
知らせ方は伝え方(`masterNicknameNotify`)に従い、`mention` なら[メンションの投稿](#伝え方)(頼んだ人の投稿への返信。公開範囲やチャットで頼まれたときの扱いも通常と同じ)、`chat` と `off` ならチャット。
投稿で頼まれて `mention` で知らせたときは、そのメンションの投稿が頼んだ人への返事なので、別には返さない。それ以外は、頼んだ人にも、マスターに知らせたのと同じ文を返す。
文は次の2行で、藍の中の呼び名も変えたとき(`callname` がオン)は「呼び名と表示名も変えました！」、オフなら「表示名も変えました！」。
マスターへの**チャットだけ**、最後に「（依頼者：表示名(@ユーザー名)）」の行を足す(メンションの投稿は、頼んだ人への返信の形なので、誰の依頼かが分かる)。

```
{マスター}のあだ名は「X」にしましょう！
呼び名と表示名も変えました！
（依頼者：アリス(@alice)）   ← マスターへのチャットだけ
```

メンションの投稿に失敗したときは、チャットで知らせる。

### そのほか

- 表示名を変える設定のときは、マスターへの連絡は、承認の問いかけ(または変えたことの知らせ)にまとめる。承認の問いかけは、伝え方に関わらずチャット。回数・間隔の制限は、通常と同じ。
  表示名を変えられなかったときは、通常と同じく回数の記録を戻し、「伝えられませんでした」と答える。
- 呼び名にする設定(`callname`)なら、表示名を変えたときに、藍の中のマスターの呼び名も変える。
- **元に戻す(`revert`)のは、藍が最初に変える前の表示名。** 藍が何度変えても、戻す先は最初の名前のまま。
  藍が変えたあとで、マスターが自分で表示名を変えていても、`revert` はそれを上書きして最初の名前に戻す(表示名が無かったときは、無い状態に戻す)。戻したら、次に変えるときの名前を、あらためて残す。

## データの置き場所

どれも `data/memory.json`(藍の記憶)に入る。

| データ | 置き場所 | 中身 |
|---|---|---|
| 提案への返事の待ち受け | `contexts`(`talk` モジュール。チャットは相手のユーザー ID、投稿は藍の返信の ID で探す) | `name`(提案したあだ名)、`seen`(出したあだ名)、`rerolls`(引き直した回数)、`at`(待ち受けた時刻)、`target`(ほかの人のあだ名のとき、誰のものか) |
| 頼んだ人の回数 | `friends` の、その人の `perModulesData.talk.masterNickname` | `date`(日付)、`count`(その日に伝えた回数) |
| 最後にマスターに伝えた時刻 | `moduleData` の `talk` の `masterNicknameNotifiedAt` | ミリ秒 |
| コマンドで変えた設定 | `moduleData` の `masterNickname` の `overrides` | `enabled`・`notify`・`mentionVisibility`・`updateName`・`perUserDaily`・`intervalMinutes` |
| 表示名の変更 | `moduleData` の `masterNickname` の `rename` | `on`、`mode`、`token`(マスターのトークン)、`userId`、`pending`(承認待ち: `item`・`from`・`at`)、`originalName`・`hasOriginal`(最初に変える前の名前)、`lastProblem`(最後に知らせた、許可の問題) |

許可の検証の結果は、記憶には残さない(起動のたびに確かめ直す)。

## 既知の制限

- チャットで「別の話だけど」のように、引き直しの言葉(「別の」)で始まる発言は、提案への返事(引き直し)とみなす。
- 半角カタカナの「ｱﾀﾞﾅ」には反応しない。
- 「a@bさんのあだ名」のように、メンションでない〇〇に「@」があると、「@」より前だけを名前として拾う(敬称が無くなり、本人のあだ名になる)。
- マスターに伝える間隔は、誰からの依頼でもまとめて数える(1人が頼むと、ほかの人もしばらく頼めない)。
- 敬称の「たん」は、ほかの語と取り違えやすいので入れていない。
